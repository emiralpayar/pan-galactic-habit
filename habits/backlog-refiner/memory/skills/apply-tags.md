# Apply tags

## When to use

The work item has no tags, or is missing a tag that the team already uses for its area or kind of work, which would help it surface in backlog queries.

## Steps

1. Read the item's existing Tags and its Description.
2. Look at the tags already used on other work items you have read in this session, if any, to find the team's existing vocabulary.
3. Propose only tags drawn from that existing vocabulary that describe the item's area or kind of work.
4. Keep every tag already on the item; propose additions, not replacements, unless an existing tag is a clear duplicate (for example, differing only in case).

## Rules

- Never invent a new tag the team has not already used elsewhere in the items you have read.
- Do not propose a tag for information already captured by another field (for example, a tag that just repeats the title).
- If no existing tag vocabulary is visible in what you have read, do not propose a Tags change: report that there is nothing to match against.

## Examples

### Good

Other items read in this session use `area:auth`, `area:billing`, `needs-design`.
This item is about a login validation bug and is currently untagged.

Proposed Tags: `area:auth`

This reuses an existing team tag that matches the item's area, without inventing a new one.

### Bad

Proposed Tags: `login-bug-2026`

This invents a one-off tag no other item uses, which will not help anyone find related work later.
